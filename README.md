# 보고서 도우미 시스템

근거를 한 번 저장해 두면, 보고서를 쓸 때 필요한 근거만 끌어오고, 지금 가장 중요한 보고서부터 쓰게 하며, 쓰는 동안 근거의 빈틈을 알려 주는 보고서 작성 도구입니다. 도메인은 포워딩·물류(운임 비교·선사 계약·클레임·정기 현황 보고)입니다.

- 시연: https://trace-to-fix.vercel.app (샘플 데이터). 헤더의 **▶ 3분 데모** 또는 `?demo=1`로 가이드 시작. `main`에 push하면 Vercel에 자동 배포됩니다.
- 사양 변경·결정 기록: [`docs/spec-addendum.md`](docs/spec-addendum.md) · 발표용 한계: [`docs/limitations.md`](docs/limitations.md)

## 흐름

근거 저장 → 보고서 작성(근거 끌어오기) → 작성 중 점검(주장–근거 역추적) → 제출 → 반려·미열람·중복 발견 → 저장 규칙 개선. 우선순위 엔진이 이 전체 위에서 "지금 어떤 보고서를 먼저 쓸지"를 다시 정렬합니다.

| 화면 | 내용 |
|---|---|
| 오늘의 보고서 | 우선순위 상위 3건과 이유·점수 구성, 업무 TODO, 읽히지 않는 보고서·항목(HS 코드 교차 보호), 가중치 슬라이더 |
| 작성 | 주장 하이라이트, 근거 끌어오기(출처·저장일·유효기간·범위), 결정 적용 시점 기준 점검, 확인 요청 상위 3개, 금액 민감도 |
| 근거 보관함 | 근거 목록·사용된 보고서·중복/분기 표시, 저장 시점 점검(승인된 필수 항목), 약한 근거 목록 |
| 동일 내용 문서 | 유사도 후보 → 핵심 항목 검증 → 이력 역추적 → 원인·제안, 병합 승인 시 보관함·보고서 링크 반영 |
| 분석 도구 · 재작업 역추적 | 반려된 보고서의 재작업 항목이 저장·끌어오기·작성·제출 중 처음 틀린 단계, 저장 필수 항목 승인 |
| 분석 도구 · 논리 역추적 | 붙여넣은 보고서의 AI 분해(실시간) + 규칙 점검, KOTRA 권역 경제 지표 |

## 원칙

- 만료·충돌·범위·금액·우선순위는 **코드 규칙**이 판정합니다(`src/rules/`, 규칙 1개 = 파일 1개 + 메타데이터). AI는 문장 나누기·사유 분류 제안만 합니다.
- 결과는 판정이 아니라 담당자가 확인할 점검 항목입니다. 사람이 승인하기 전에는 어떤 규칙도 양식에 반영되지 않습니다.
- 확인 요청은 보고서당 상위 3개만 보이고 나머지는 접습니다. 개인명은 저장하지도 표시하지도 않습니다.
- 화면의 숫자는 샘플 데이터에서 코드로 계산하며, 샘플이라 통계적 결론이 아님을 화면에 밝힙니다.

## 실행

AI 기능(반려 사유 분류, 보고서 분해)을 쓰려면 `.env.example`을 `.env.local`로 복사하고 `OPENAI_API_KEY`(필요하면 `OPENAI_MODEL`)를 채웁니다. 배포 환경에서는 Vercel 환경변수에 같은 이름으로 넣습니다. 키는 서버 함수(`api/`)에서만 읽습니다.

```bash
npm install
npm run dev          # 개발 서버(/api 포함)
npm test             # 단위 테스트(Vitest)
npm run build        # 타입 검사 + 빌드
npm run data:kotra   # KOTRA 권역별 경제 지표 갱신(data.go.kr 파일 데이터)
```
