# 업무 역추적 시스템 (Trace-to-Fix)

서류가 수정·반려되거나 문서가 어긋날 때, 기록을 결과에서 원인으로 거꾸로 따라가 문제가 처음 생긴 단계를 찾고, 양식·규칙을 고쳐 같은 문제가 다시 생기지 않게 하는 시스템입니다. 도메인은 포워딩·물류(부킹, SI, 인보이스, 패킹리스트, B/L)입니다.

- 시연: https://trace-to-fix.vercel.app (가상 시드 데이터)
- 사양 변경·추가 기록: [`docs/spec-addendum.md`](docs/spec-addendum.md)

## 모듈

| 탭 | 내용 | 상태 |
|---|---|---|
| ① 재작업 역추적 | 단계별 타임라인, 최초 원인 단계, 패턴 집계, 개선안, 가상 재실행 | 구현 |
| ② 논리 역추적 | 보고서 결론·주장·근거·가정 분해와 약한 고리 점검 | 예정 |
| ③ 동일 내용 문서 | 제목이 다른 같은 내용 문서의 분기 지점·값 불일치 | 예정 |
| ④ 업무 관성 탐지 | 결과가 쓰이지 않는 승인·보고·입력 항목을 폐지 후보로 제안 | 구현 |

## 원칙

- 역추적 대상은 사람이 아니라 단계·양식·규칙입니다. 개인명은 저장하지도 표시하지도 않습니다.
- AI·규칙이 찾은 원인은 추정이며 `담당자 확인 필요`를 붙입니다. 사람이 승인하기 전에는 어떤 규칙도 적용되지 않습니다.

## 실행

```bash
npm install
npm run dev          # 개발 서버
npm test             # 단위 테스트(Vitest)
npm run build        # 타입 검사 + 빌드
```

## 구조

```
src/domain/   순수 함수: 역추적(trace), 패턴·가상 재실행(patterns), 업무 관성(zombie), 스키마(zod)
src/seed/     시드 JSON(사건·단계 기록·보고서·문서·절차)
src/modules/  탭별 화면
```
