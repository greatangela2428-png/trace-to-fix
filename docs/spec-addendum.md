# 사양 추가·변경 기록

원본 사양: `vibe_coding_prompt.md`. 아래는 구현하면서 추가하거나 바꾼 내용이다.

## 모듈 4 — 업무 관성 탐지 (Zombie Task Finder)

**문제:** 과거에 필요했던 절차가 도입 이유를 잊은 채 계속 남아 있다.
**한 줄 정의:** 승인·보고·입력 항목마다 "왜 생겼는지, 결과가 마지막으로 쓰인 때"를 추적해, 결과가 쓰이지 않는 절차를 폐지 후보로 제안한다. 업무를 더하는 대신 빼는 AI.

### 데이터 (`Procedure`)
- 종류: `APPROVAL`(승인 단계) / `REPORT`(보고서) / `INPUT_FIELD`(입력 항목)
- 도입 시점·이유·근거 문서, 법정 근거(`legalBasis`), 건당 처리 시간, 승인 평균 대기
- 월별 `executed`(실행 건수)와 `outcome`(결과가 쓰인 건수: 승인=반려·수정, 보고서=열람, 입력 항목=후속 단계 참조)
- 실행자는 저장하지 않는다(원칙 2·6).

### 판정 규칙 (`findZombies`, 코드로 수행)
기준일 직전 12개월을 본다. 위에서부터 먼저 맞는 규칙을 적용한다.
1. 법정 근거가 있으면 → **제외**
2. 입력 항목이 모듈 1에서 재작업 원인 필드로 확인됐으면 → **유지**(빼면 오류가 늘 수 있음)
3. 실행이 기준(기본 12건) 미만이면 → **판단 보류**(드물지만 중요한 통제일 수 있음)
4. 결과가 쓰인 건수가 0이면 → **폐지 후보**
5. 그 밖에는 → **유지**

도입 이유가 기록되지 않았으면 별도로 "도입 배경 확인 필요"를 표시한다.

### 원칙 반영
- 폐지 후보에는 모두 `담당자 확인 필요` 배지를 붙인다. 자동 폐지는 하지 않는다.
- 제안은 즉시 폐지가 아니라 **3개월 시범 중단 후 재평가**다. 승인은 두 번 눌러야 확정되고, 되돌릴 수 있다.
- 모듈 1의 "규칙 수명 관리"와 짝을 이룬다. 모듈 1이 더한 규칙도 결국 이 모듈의 추적 대상이 되어 "더하기 → 빼기"가 순환한다.

## 기존 모델 확장
- `ReworkCase`: `label`(목록 표시용), `reworkText`(반려 메일 원문, 5단계 자동 분류 입력)
- `Evidence.figures`: 수치 충돌 점검용 항목별 수치
- `Report`: 제목·결론·본문·주장 묶음
- `Suggestion.kind`: `CROSS_CHECK`(서류 간 자동 대조), `PAUSE_PROCEDURE`(시범 중단) 추가
- `Suggestion`: `field`, `patternKey` 추가(가상 재실행 대상 식별)

## 동작 결정
- 같은 단계에 기록이 여러 개면 가장 늦은 값을 쓴다. 기록이 없는 단계는 원인으로 지목하지 않는다.
- 가상 재실행: 필수 항목화는 같은 단계에서 시작된 같은 필드의 누락만 예방으로 센다. 자동 대조는 "조기 발견 가능"으로만 표시하고 예방 건수·절감액에 넣지 않는다. 사전 점검·체크리스트는 과거 기록으로 효과를 추정할 수 없어 "적용 후 전후 비교"로 안내한다.
- 첫 단계(부킹)에서 시작된 오입력에는 대조할 앞 단계가 없으므로, "화주 원본 자료와 대조하는 확인 질문"을 제안한다.
- "개인명 비표시 모드"는 끌 수 있는 토글 대신 **항상 켜짐** 표시로 둔다. 개인명을 저장하지 않으므로 끌 대상이 없다.
- 시연 기준일은 `AS_OF = 2026-11-05`로 고정한다(`src/seed/index.ts`). 실데이터를 연동할 때 오늘 날짜로 바꾼다.

## AI 호출 (OpenAI)

- 제공자: OpenAI Responses API, 구조화 출력(JSON Schema strict) + zod 재검증
- 모델: 코드 기본값은 `gpt-5-mini`. 해커톤 주최사 키의 프로젝트가 `gpt-5.4-mini`만 허용해서 `OPENAI_MODEL=gpt-5.4-mini`로 운영한다(`.env.local`, Vercel 둘 다)
- 키: `OPENAI_API_KEY`(해커톤 주최사 제공). 로컬은 `.env.local`, 배포는 Vercel 환경변수. 서버 함수(`api/`)에서만 읽고 브라우저 번들에는 포함되지 않는다. 키를 바꿀 때는 `scripts/set-openai-key.ps1`(클립보드 → 검증 → 두 곳 교체)
- 공통 서버 코드: `server/openai.ts`(호출·1회 재시도), `server/http.ts`(출처 차단·본문 검증·오류 안내)
- 첫 기능: 반려 사유 자동 분류 `POST /api/ai/classify-reason` (원래 5단계 항목을 앞당김)
  - 신뢰도 0.6 미만, 근거 인용이 원문에 없음, `OTHER` 중 하나면 `기타`로 두고 사람에게 묻는다
  - 형식 오류 시 1회 재시도. 모델에 보내기 전 이메일·전화번호를 가린다
  - 결과는 제안일 뿐이며, 사람이 "이 사유로 확정"을 눌러야 확정된다(AI 제안 확인 / 사람 수정 구분 기록)
- 공개 사이트 보호: 다른 출처의 호출 차단, 본문 2,000자 제한. 호출 횟수 제한은 없으므로 OpenAI 대시보드의 사용 한도 설정을 권장

## 모듈 2: 논리 역추적 (3단계에서 정한 것)

- 역할 분리: AI(`POST /api/ai/decompose-report`)는 보고서를 결론·주장·근거·가정으로 **나누기만** 하고, 약한 고리 판정은 브라우저의 `checkReport`(코드 규칙, `src/domain/logic.ts`)가 한다
- 규칙 5종: 유효기간 만료(`validUntil < 기준일`), 출처 불명확, 가정 근거 없음, 비교 대상 누락, 수치 충돌
  - **근거가 하나도 없는 주장**도 "출처 불명확"으로 본다(사양 5-2 "연결 실패 시 출처 불명확")
  - 비교 대상 누락은 **그 주장 문장**에 대상이 나오는지로 본다(공백 차이 무시)
  - 수치 충돌은 보고서 전체에서 같은 항목명의 값이 다르면 1건으로 묶는다
- AI 출력 안전장치: 주장 문장이 원문에 그대로 없으면 "원문에서 문장 확인 안 됨" 표시, 없는 날짜(예: 2월 30일)는 버림, 연락처는 가린 뒤 전송, 본문 6,000자 제한
- 샘플 보고서는 미리 분해된 데이터로 AI 없이 바로 점검된다. 본문에 `[근거 자료]` 목록을 넣어, 같은 본문을 AI로 분해해도 시연 포인트(만료 운임표, 1,850 vs 1,920 충돌, 환율 가정, 홍보 자료 출처, B 선사 비교 누락)가 나오게 했다(실제 gpt-5.4-mini로 확인)

## KOTRA 공공데이터 연동 (2026-11-06 사용자 요청, 서비스키 없이)

- 사용자 결정: data.go.kr 서비스키 없이 **로그인 없이 받는 파일 데이터만** 쓴다. 해외시장뉴스·무역사기사례·국가정보·국가별 물가는 오픈API 전용이라 제외(키가 생기면 추가 가능)
- `npm run data:kotra`(`scripts/import-kotra.mjs`): data.go.kr에서 내려받아 JSON으로 변환. 결과 파일은 커밋해서 배포가 포털 상태에 좌우되지 않게 한다
  - 수입규제 15128187(공공누리 제3유형 **변경금지**) → `public/kotra/import-regulations.json`(1.6MB, ⑤ 탭을 열 때 불러옴). 값은 그대로 두고 구조만 정리(진행 상황은 마지막 괄호에서 분리, 'ㅇ 부과기간 :' 같은 머리말만 제거)
  - 권역별 경제 지표 15128914 → `src/data/kotra/econ.json`, 외교부 국가표준코드 15091117 → `countries.json`
- **⑤ 수출 사전 점검** 탭(사양 확장): HS 코드(4자리 이상) + 목적국 → 반덤핑·상계관세·세이프가드·우회수출. 나라마다 HS 자릿수가 달라 **앞 6자리까지만** 비교, 4단위 규제는 "더 넓은 분류"로 표시. 결과가 없어도 "규제 없음"이라 하지 않고 비관세 요건은 따로 확인하라고 안내. 시드 예약 중 HS 코드가 있는 건은 자동 점검
- **② 논리 역추적 보조**: 본문에서 권역을 찾아(항구명 포함) 가정 주제(물동량·물가·경기)에 맞는 KOTRA 지표를 "참고 지표"로 표시. 환율·해상운임은 KOTRA 파일에 없다고 명시. 비율이 아닌 지표가 전년 대비 5배 이상 변하면 "원자료 확인 필요"(값은 고치지 않음, 예: 북미 인구 2025 = 387)
- 모든 KOTRA 화면에 출처·이용조건·내려받은 날짜를 표시한다

## 보고서 내보내기·디자인 개편 (2026-11-06 사용자 요청)

- 헤더의 **보고서 내보내기**: 기간(최근 1·3·6·12개월)과 포함할 내용(사건 이력, 패턴, 제안·승인, 논리 점검, 업무 관성, 수출 사전 점검)을 골라 받는다
  - 내용은 `src/export/report.ts`의 `buildReport`(순수 함수) 하나로 만들고, 엑셀과 PDF가 같은 결과를 그린다
  - **엑셀**: `write-excel-file`(의존성 없음, 누를 때만 불러옴). 요약 시트 + 섹션별 시트, 금액은 숫자 서식
  - **PDF**: 인쇄 전용 A4 레이아웃 + 브라우저 인쇄 창("PDF로 저장"). JS PDF 라이브러리는 한글 글꼴을 수 MB 넣어야 해서 쓰지 않았다. 대신 한글이 선명하고 글자 복사가 된다
  - 사람이 확정한 반려 사유가 시드 사유보다 우선. 개인명 열 없음
- 디자인: 항만·바다 톤 색, Pretendard 글꼴, 둥근 카드·알약 모양 탭/배지, 첫 화면 히어로(항만 일러스트 SVG + 핵심 숫자 4개), 탭마다 아이콘 소개. 일러스트는 외부 이미지 없이 인라인 SVG(`src/components/infographics.tsx`)라 테마 색을 따르고 PDF 표지에도 쓴다
