# 발표에서 정직하게 말할 것: 이 시스템이 하지 못하는 것

앱 화면 맨 아래 **"이 시스템이 하지 못하는 것"**에서도 같은 내용을 볼 수 있습니다(`src/screens/common/InfoDialogs.tsx`의 `LIMITATIONS`).

1. **샘플 데이터** — 보고서 5건, 근거 16건, 반려 13건, 선적 재작업 13건은 시연용 샘플입니다. 건수·비율·방지 효과는 통계적 결론이 아닙니다.
2. **우선순위·점수 가중치는 초기 가정** — 우선순위 식(영향도 × 임박도 × 준비 부족도 × 독자 중요도)과 기준값, 점검 항목 점수, TODO 가중치, 재작업 시간당 5만 원은 모두 초기 가정입니다. 팀이 합의해 정해야 합니다.
3. **작성 화면은 미리 분해된 보고서** — 작성 화면의 보고서는 주장·근거 연결이 미리 들어 있습니다. 새 보고서의 실시간 AI 분해는 논리 역추적 화면에서만 되고, 그 결과를 작성 화면으로 옮기는 기능은 없습니다.
4. **근거 추천은 코드 매칭** — 값 항목 이름·범위·낱말 일치로 고르므로, 의미가 같은데 표현이 다르면 놓칠 수 있습니다.
5. **범위 계층·운임 구성은 규칙표 기반** — 항로 계층(유럽 항로 ⊃ 부산-로테르담 등)과 '포함 항목' 판단은 샘플 항로·필드에 맞춘 규칙표입니다. 실제 항로 마스터·운임 체계와 연결해야 합니다.
6. **열람 지표의 한계** — 읽히지 않는 보고서 판단은 시스템 열람 로그 기준이라 인쇄·구두 공유는 빠집니다. 그래서 자동 폐지 대신 사람의 결정(유지·시범 중단·표본 감사)을 받습니다.
7. **저장되지 않는 상태** — 승인·병합·응답·근거 수정은 새로고침하면 샘플 상태로 돌아갑니다(피로도 집계만 브라우저에 저장). 실제 운영에는 서버 저장이 필요합니다.
8. **재발 모니터링 데이터 없음** — 저장 필수 항목 승인 후 같은 사유의 반려가 줄었는지는 승인 후 반려 기록이 있어야 알 수 있어, 지금은 보관함의 빈 항목 수만 보여 줍니다.
9. **동일 내용 문서의 유사도** — 시드에 넣은 8차원 샘플 임베딩으로 계산합니다. 실제 문서 임베딩이 아닙니다.
10. **개인 단위 평가 없음** — 담당자 이름을 저장·표시하지 않으므로 "누가 자주 틀리나"는 볼 수 없습니다. 의도한 설계입니다.
